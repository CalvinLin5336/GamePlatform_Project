# 房間系統串接 Game Management

房間系統使用 `GameManagementService` 取得資料，不要直接操作 Repository。

## 方法一覽

| 用途 | 完整方法 | 參數 | 回傳型態 |
|---|---|---|---|
| 取得所有可選遊戲 | `GameManagementService.findEnabledGames()` | 無 | `List<GameView>` |
| 根據 ID 取得完整遊戲資料 | `GameManagementService.findGame(Long gameId, boolean admin)` | `gameId`：遊戲 ID；房間系統固定傳 `false` | `GameView` |
| 取得所選遊戲的模式 | `gameView.getModes()` | 無 | `List<GameModeView>` |

## 1. 取得遊戲下拉選單

```java
@Autowired
private GameManagementService gameSystemService;

List<GameView> games = gameSystemService.findEnabledGames();
```

這個方法沒有參數，只回傳已啟用的遊戲。下拉選單使用：

```text
選項值：game.getGameId()
顯示文字：game.getGameName()
圖片：game.getImagePath()
```

每個 `GameView` 包含：

```text
gameId、gameCode、gameName、description、frontendPath、
backendPath、imagePath、enabled、modes
```

## 2. 根據 gameId 查詢遊戲

```java
Long gameId = request.getGameId();
GameView game = gameSystemService.findGame(gameId, false);
```

| 參數 | 型態 | 房間系統傳入內容 |
|---|---|---|
| `gameId` | `Long` | 玩家選擇的遊戲 ID |
| `admin` | `boolean` | 固定使用 `false`，只允許已啟用的遊戲 |

回傳型態是 `GameView`。如果 gameId 不存在或遊戲未啟用，Service 會拋出錯誤，不應建立房間。

## 3. 取得模式下拉選單

```java
GameView game = gameSystemService.findGame(gameId, false);
List<GameModeView> modes = game.getModes();
```

下拉選單使用：

```text
選項值：mode.getModeId()
顯示文字：mode.getModeName()
```

每個 `GameModeView` 包含：

```text
modeId、gameId、modeCode、modeName、minPlayers、maxPlayers、
computerPlayers、enabled
```

## 4. 產生真人玩家人數選單

```java
for (int players = mode.getMinPlayers();
        players <= mode.getMaxPlayers();
        players++) {
    // 把 players 加入下拉選單
}
```

若 `minPlayers=2`、`maxPlayers=4`，選單顯示 `2、3、4`。這兩個欄位只計算真人，不包含 `computerPlayers`。

## HTTP API

| 用途 | 方法與路徑 | 回傳內容 |
|---|---|---|
| 所有可選遊戲 | `GET /api/game-management/games` | JSON 陣列，對應 `List<GameView>` |
| 單一遊戲 | `GET /api/game-management/games/{gameId}` | JSON 物件，對應 `GameView` |

前端目前會附上平台 JWT；是否由後端強制驗證仍取決於共用
`SecurityConfig`。目前 `/api/games/**` 尚未被共用設定限制，不能只靠前端傳送
header 當成已完成授權：

```http
Authorization: Bearer JWT
```

回傳範例：

```json
{
  "gameId": 1,
  "gameCode": "POKER",
  "gameName": "田忌撲克",
  "frontendPath": "/src/pages/Games/poker/poker_client.html",
  "backendPath": "/api/games/poker",
  "imagePath": "/src/assets/Games/poker/poker_game_icon.png",
  "enabled": true,
  "modes": [
    {
      "modeId": 1,
      "gameId": 1,
      "modeCode": "COMPUTER",
      "modeName": "對戰電腦",
      "minPlayers": 1,
      "maxPlayers": 1,
      "computerPlayers": 1,
      "enabled": true
    },
    {
      "modeId": 2,
      "gameId": 1,
      "modeCode": "PLAYER",
      "modeName": "玩家對戰",
      "minPlayers": 2,
      "maxPlayers": 2,
      "computerPlayers": 0,
      "enabled": true
    }
  ]
}
```

## 建立房間

房間至少保存：

```text
gameId、modeId、requiredPlayers
```

未輸入房間名稱時，可使用 `game.getGameName() + "-" + roomId`，例如 `田忌撲克-15`。

## 開始遊戲

不要寫死頁面路徑，應讀取：

```java
String frontendPath = game.getFrontendPath();
```

目前 Lobby 開始遊戲時只把房號放進入口網址：

```java
String gameUrl = game.getFrontendPath() + "?room=" + roomId;
```

網址範例：

```text
/src/pages/Games/poker/poker_client.html?room=15
```

| 參數 | 用途 |
|---|---|
| `room` | 平台房間 ID；Poker 前端會先讀取 Lobby 房間資料 |

Poker 前端取得 Lobby 房間的 `modeId` 後，呼叫 Poker join API 時傳送
`roomId`、`modeId` 與平台 JWT。Poker 後端從 JWT 取得 `userId`、`account` 與顯示名稱，
再用 `account` 核對 Lobby 的 `hostAccount`／`room_players.playerAccount`。
`PLAYER` 的兩位真人由 Poker 隨機分配座位 1、2，同一個 userId 重連時維持原座位；
`COMPUTER` 的真人固定為座位 1。Lobby 不傳 `seat` 或 `playerName`。

目前 Poker 以 `PokerPlatformRoomService` 讀取 Lobby Room，並以 `PokerJwtService`
查詢平台會員。Lobby Room 與 Poker 記憶體對局的結束、離場及清理仍需另行統一。

## 不要直接使用

- `GameRepository`
- `GameModeRepository`
- Game Management 的 model/entity

這些是 Game Management 內部資料存取層，房間系統使用 `GameManagementService` 和 DTO 即可。
